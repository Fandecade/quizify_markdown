# Quizify Markdown CSV 制卡规范（AI 批量制卡版）

面向对象：需要批量生成 Anki 卡片的 AI / 脚本。
目标产物：一个 UTF-8 的 `.csv` 文件，导入时自动落到**指定笔记类型**（`Quizify Markdown`）
与**指定牌组**，字段里可以直接写全部 Quizify 语法。

对应版本：Anki 25.09+ 的内置 CSV 导入器；笔记类型 `Quizify Markdown`（字段 `Front` / `Back`）。

本文所有结论都在真实 Anki 25.9.5 上实测验证（文件头指令、列映射、引号内换行、
`#` 开头行、`#html` 两种模式、牌组自动创建）。

---

## 0. 一分钟骨架

```csv
#separator:comma
#html:false
#notetype:Quizify Markdown
#deck:学习::网络
#columns:Front,Back,tags
#tags column:3
"第一张题面","第一张答案","网络 每日"
"第二张题面","第二张答案","网络"
```

把这 6 行头指令写在文件最前面，Anki 导入面板就会自动选好笔记类型 `Quizify Markdown`
和牌组 `学习::网络`，列名自动对上 `Front` / `Back` / 标签列。

---

## 1. 先选路线：CSV 还是 .md

| 能力 | CSV（本文） | Quizify Card Markdown `.md` |
| --- | --- | --- |
| 指定笔记类型 / 牌组 | 文件头 `#notetype` / `#deck` | YAML front matter |
| 单元格内换行 | 引号内真换行（推荐）或 `<br>` | 原生换行 |
| 图片自动入库 | ❌ 不复制，只认已有媒体库文件名 | ✅ `media.local: copy` 自动复制并改写 |
| 微信/AI 生成难度 | ✅ 最简单（表格模型天然会 CSV） | 需要懂缩进与分隔标记 |
| 手机导入 | AnkiDroid 可用；AnkiMobile 基本不支持 | 同样不能直接导入，需 `.apkg` |
| 幂等再导入 | ✅ `#guid column` + `#if matches` | ❌ 只新建 |

**结论**：批量制卡用 CSV 最顺；但**媒体文件不会随 CSV 进入媒体库**，跨设备看图的
唯一可靠做法仍然是最后打成 `.apkg`（见第 6 节）。

## 2. 文件头指令（实测有效）

指令必须写在**文件最前面的连续若干行**，以 `#` 开头，格式 `#键:值`。
出现第一个非 `#` 行（含空行）就结束头块。没有冒号的 `#` 行也会被整行忽略。

| 指令 | 取值 | 作用 |
| --- | --- | --- |
| `#separator:` | `comma` / `tab` / `pipe` / `semicolon` / `colon` / `space`，或单个字面字符（如 `;`） | 指定分隔符；不写则自动探测 |
| `#html:` | `true` / `false` | 单元格内容是否按 HTML 处理（见第 5 节） |
| `#notetype:` | 笔记类型名称或 ID | 目标笔记类型 |
| `#deck:` | 牌组名称或 ID；`::` 表示子牌组 | 目标牌组，**不存在会自动创建**（含父级） |
| `#tags:` | 空格分隔的标签 | 加给全部卡片 |
| `#columns:` | 逗号/当前分隔符分隔的列名 | 用于按字段名自动映射 |
| `#tags column:` | 列号（从 1 开始） | 该列内容按空格拆成标签 |
| `#deck column:` | 列号 | 逐行指定牌组 |
| `#notetype column:` | 列号 | 逐行指定笔记类型 |
| `#guid column:` | 列号 | 逐行指定 GUID，用于再导入时匹配已有笔记 |
| `#match scope:` | `notetype` / `notetype + deck` | 判重范围 |
| `#if matches:` | `update current` / `keep current` / `keep both` | 命中已有笔记时的处理 |

三条容易踩的规则：

1. **`#separator:` 必须写在 `#columns:` 之前**。`#columns:` 用「当时已知的分隔符」切分，
   而默认分隔符是 TAB；顺序写反会把列名切错。
2. **`#notetype:` 名字写错不会报错**，会静默回退到导入面板的默认笔记类型。
   所以务必确认 `Quizify Markdown` 已存在于该资料库（装好加载项，或先导入一次 `.apkg`）。
3. `#deck:` 允许写不存在的名字（会自动建）。手机端同步依赖 AnkiWeb，牌组名保持一致即可。

---

## 3. 列 → 字段映射

- 写了 `#columns:`：按**字段名精确匹配**（区分大小写）。`Quizify Markdown` 的字段名是
  `Front` 和 `Back`，所以要写 `#columns:Front,Back`（后面可以再跟着 `tags` 等名字）。
- 没写 `#columns:`：按**列序**映射，第 1 个普通列 → `Front`，第 2 个 → `Back`。
- 被 `#tags column:` / `#deck column:` / `#notetype column:` / `#guid column:` 指定的列是
  **元数据列**，不参与字段映射，可以放在任意位置。
- 列名对不上字段名时该字段留空，不会报错——所以名字写错会得到「空卡片」，
  务必对照 `#columns:` 检查。

实测例：

```csv
#separator:comma
#notetype:Quizify Markdown
#columns:Front,Back,tags
#tags column:3
"题面","答案","标签A 标签B"
```

导入后：`Front` = 题面、`Back` = 答案、标签 = `标签A`、`标签B`，牌组按 `#deck:`。

## 4. 单元格转义（RFC 4180）

- 字段里含**逗号、双引号、换行**时，整个字段用 `"` 包起来。
- 字段内部的 `"` 写成 `""`（两个双引号）。

  ```csv
  "遮住关键词","TCP 是一种 %%面向连接%%、可靠的 %%传输层协议%%。",网络
  ```

- 行尾统一用 `\n`（LF），文件编码 UTF-8（允许 BOM）。
- 引号内的换行 Anki 会保留（已实测），这是写多行 Quizify 语法的前提。

---

## 5. 在单元格里写 Quizify 语法（关键）

### 方案 A（推荐）：`#html:false` + 引号内真实换行

```csv
#html:false
"三次握手在哪一层？",";;;
A. 应用层
B. 传输层
C. 网络层
;;;B"
```

实测结果：导入后字段存储为 `;;;<br>A. 应用层<br>B. 传输层<br>C. 网络层<br>;;;B`，
Quizify 渲染时再把 `<br>` 还原成换行并解析成选项组件，**手机上同样正常**。

优点：正文里的 `<`、`>`、`&` 会被自动转义成 `&lt;` 等，不会丢内容，AI 可以放心写字面量。

### 方案 B：`#html:true` + 手工 `<br>`

```csv
#html:true
"三次握手在哪一层？",";;;<br>A. 应用层<br>B. 传输层<br>C. 网络层<br>;;;B"
```

单元格内容按 HTML 原样保存，换行必须自己写 `<br>`。
**代价**：正文里的 `<`、`>`、`&` 必须手写成 `&lt;` `&gt;` `&amp;`，否则会被当 HTML 标签
吞掉（实测 `<原文>` 会直接消失）。只有在单元格本身就是 HTML 时才用方案 B。

### 两种方案共同注意

- 所有 Quizify 块（`;;;`、`:::`、`::::`、`===`）必须**各自独占一行**，也就是每个标记
  前后都要有一次换行，不能和文字挤在同一行。
- 空行也要保留：卡片段落之间、块标记与内容之间，靠连续两次换行（方案 A 里就是
  CSV 单元格中的空行）来实现。
- `---`、`***`、`+++` 这套是 `.md` 导入的分隔标记，**在 CSV 里没有意义**，
  不要写；CSV 一行就是一张卡。

## 6. 媒体：CSV 最大的坑

CSV 导入**不会**复制图片到媒体库，也**不会**改写字段里的文件名。所以：

- 字段里引用的名字必须是**已经在 Anki 媒体库（`collection.media`）里的文件名**：

  ```csv
  "看这张图","![协议栈](网络协议栈.png)"
  "遮住关键词","TCP 用 %%三次握手%% 建立连接。"
  ```

- 放入媒体库的方式：桌面端 `工具 → Quizify Markdown → 导入图片到媒体库…`，
  或直接把文件拖进 `collection.media` 再执行「检查媒体」。
- 入库后桌面端通过 AnkiWeb 同步会把媒体一起带到手机，**手机端才能看到图**。
- 绝对路径、`./`、`../`、`C:\...`、`![[...]]` 一律不要写，手机端只会显示一串路径文字。
- 手机端导入能力：AnkiDroid 有 CSV 导入（新版走同一套后端）；**AnkiMobile 基本不支持
  CSV 导入**。要覆盖全部手机端，最后仍应导出 `.apkg`（见下一条）。

### 推荐工作流

1. AI 生成 `.csv`；
2. 桌面端 Anki 导入 CSV（头指令自动选好 `Quizify Markdown` + 目标牌组）；
3. 图片用「导入图片到媒体库…」补齐；
4. 需要发给手机时，把牌组导出成 `.apkg`，或直接用
   `python tools/build_apkg.py` 生成带模板与运行时的包。

## 7. 完整示例文件

```csv
#separator:comma
#html:false
#notetype:Quizify Markdown
#deck:学习::网络
#columns:Front,Back,tags
#tags column:3
"# 端口

HTTP 的默认端口是 {{80}}，HTTPS 是 {{443}}。","应用层协议：HTTP 80、HTTPS 443。","网络 每日"
"# 三次握手在哪一层

;;;
A. 应用层
B. 传输层
C. 网络层
D. 数据链路层
;;;B","传输层。三次握手 = SYN → SYN/ACK → ACK。","网络 重点"
"# 先想再看

TCP 建立连接前需要做什么？ [[想一想||三次握手]]","先完成三次握手，再传输数据。","网络"
"# 对比 TCP 与 UDP

=== TCP
可靠、有序、面向连接。
=== UDP
轻量、无连接、不保证可靠。
===","","网络"
"# 文字遮盖：传输层要点

TCP 是一种 %%面向连接%%、可靠的 %%传输层协议%%，用 %%三次握手%% 建立连接。","点遮盖块揭示，再点一次盖上。","网络"
"# 图片：协议栈

![网络协议栈](网络协议栈.png)","图片名必须是媒体库里的文件名。","网络"
```

注意含逗号的字段必须整体用双引号包裹，字段里的双引号要写成 `""`——这是 CSV 的
标准转义，AI 生成时必须这么写。

## 8. 幂等再导入（可选，进阶）

AI 每次重新生成整份 CSV 时，若想「更新」而不是「重复添加」，加两列：

```csv
#separator:comma
#notetype:Quizify Markdown
#deck:学习::网络
#columns:Front,Back,guid
#guid column:3
#match scope:notetype + deck
#if matches:update current
"题面","答案","quizify-net-0001"
```

- `#guid column:` 指定一列作为稳定 ID，再导入时按它匹配已有笔记。
- `#match scope:notetype + deck` 限定只在同一笔记类型 + 同一牌组内匹配（更安全）。
- `#if matches:` 三个取值：`update current`（更新）、`keep current`（跳过）、`keep both`（都保留）。
- GUID 用短 ASCII 字符串、不含空格、全局唯一且稳定（例如 `quizify-<主题>-<序号>`）。
  不想引入 GUID 就省略这一列，Anki 默认按「首字段内容相同」判重。

## 9. 常见错误速查

| 现象 | 原因 | 修正 |
| --- | --- | --- |
| 卡片进了错误的笔记类型 | `#notetype:` 名字写错会静默回退 | 核对名称，或确认已导入过一次 `.apkg` |
| 卡片全进了默认牌组 | `#deck:` 拼写/被对话框选择覆盖 | 检查头指令；导入面板里也会显示文件指定的牌组 |
| 字段全空 | `#columns:` 列名与字段名不一致（区分大小写） | 写成 `#columns:Front,Back` |
| 列名被切碎 | `#columns:` 写在 `#separator:` 之前 | 把 `#separator:` 提到第一行 |
| 选项块不生效 | 所有标记挤在一行 | 用引号内换行（方案 A）或 `<br>`（方案 B） |
| 图片变成一串路径文字 | 字段里写了本地路径 | 只写媒体库文件名，并先入库 |
| 正文里的 `<`/`&` 消失 | 用了 `#html:true` 但没转义 | 改 `#html:false`，或写成 `&lt;`/`&amp;` |
| 单元格被逗号拆开 | 含逗号的字段没加引号 | 整个字段用 `"` 包起来 |
| 内层引号丢失 | 引号没有双写 | `"…url=""图.png""…"` |
| 重复导入产生一堆副本 | 没有 guid 列 / `#if matches:` 未设 | 见第 8 节 |
| 手机看不到图 | 媒体没同步 / 用 CSV 导入到手机 | 桌面补齐媒体并同步，或导出 `.apkg` |

## 10. 可直接粘贴给 AI 的提示词

```text
你负责生成 Anki 批量制卡用的 CSV 文件（UTF-8，LF 换行，RFC 4180）。
目标笔记类型固定为「Quizify Markdown」，字段为 Front 和 Back。

文件必须以这些头指令开头（顺序不要改）：
#separator:comma
#html:false
#notetype:Quizify Markdown
#deck:<牌组名，用 :: 表示子牌组>
#columns:Front,Back,tags
#tags column:3

之后每行一张卡：第 1 列 Front、第 2 列 Back、第 3 列是用空格分隔的标签。
含逗号、双引号或换行的字段必须用双引号包裹，字段内的双引号写成两个双引号。

字段里可以直接写 Quizify 语法（每个标记必须独占一行，用引号内的真实换行实现）：
{{答案}} 填空；;;; A. 选项 … ;;;B 选择（≥2 项、字母不重复、答案字母必须存在）；
[[题干||答案]] 揭示；[术语]^(解释)^ 批注；==高亮==；X^2^；H~2~O；$公式$；
::: 标题 … ::: 折叠；=== 标题 … === 标签页；
%%文字%% 文字遮盖（成对，行内可用，点一下揭示、再点一下盖上）。
Markdown 基础语法（标题、列表、表格、引用、代码块）照常使用。

图片只能引用已在 Anki 媒体库中的文件名，禁止绝对路径、./、../、![[...]]。
不要输出 ---、***、+++ 这些 Markdown 导入用的分隔标记。
```

## 11. 生成后自检

- [ ] 头指令在文件最前，`#separator` 在 `#columns` 之前
- [ ] `#notetype:Quizify Markdown` 拼写正确，`#deck:` 是想要的牌组（`::` 分层）
- [ ] 每行的列数与 `#columns:` 一致
- [ ] 含逗号/引号/换行的字段都用双引号包裹，内部引号已双写
- [ ] 每个 Quizify 块标记独占一行，`;;;`/`:::`/`::::`/`===` 都有闭合
- [ ] 选择块 ≥ 2 项、字母不重复、答案字母都在选项里
- [ ] 所有媒体都是媒体库文件名，没有本地路径
- [ ] 单引号文本里没有裸的 `<`、`>`、`&`（用 `#html:false` 时无此问题）
