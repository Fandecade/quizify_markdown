# 手机端 `.apkg` 打包说明

## 为什么要打包成 `.apkg`

Quizify 目前的形态是一个 **Anki 桌面端加载项（add-on）**：它通过 Python 钩子在
桌面端完成两件手机无法做到的事情：

1. 维护 `Quizify Markdown` 笔记类型（字段、卡片模板、样式）；
2. 把复习运行时 `_quizify.js` / `_quizify.css` / `_quizify-i18n.js` /
   `_persistence.js` 以及 KaTeX 字体同步到媒体库。

**AnkiDroid 和 AnkiMobile 不能安装桌面加载项。** 手机端唯一的主流分发格式是
`.apkg`（Anki 牌组包）。因此要把 Quizify 用到手机上，必须把"笔记类型 + 卡片模板 +
运行时资源 + 字体 + 示例卡片"一起塞进一个 `.apkg` 里。

这正是 `tools/build_apkg.py` 做的事情。生成的文件在桌面端、AnkiDroid、AnkiMobile
上都能通过标准的"导入文件"入口打开。

## 构建

需要 Python 3.10+，并安装带 Rust 后端的 Anki 库：

```bash
python -m pip install "anki==25.9.5"
python tools/build_apkg.py --out dist/quizify_markdown.apkg
```

也可以走 `npm`：

```bash
npm run build:apkg
```

可选参数：

- `--out PATH`：输出路径，默认 `dist/quizify_markdown.apkg`。
- `--no-samples`：只打包笔记类型，不附带示例牌组。

## 包里有什么

- `Quizify Markdown` 笔记类型，字段为纯文本 `Front` / `Back`；
- 正面 / 背面两张卡片模板 —— **直接复用 `quizify_addon/notetype.py`**，因此模板
  永远和加载项保持一致，不会各自漂移；
- 内嵌的首帧主题引导脚本与样式（进入暗色/明亮主题时不闪屏）；
- 完整的离线运行时（`_quizify.js` / `_quizify.css` / `_quizify-i18n.js` /
  `_persistence.js`）与 20 个 KaTeX WOFF2 字体；
- 一张示例图片（`_quizify-sample.png`）；
- 一个 `Quizify Markdown` 示例牌组（18 张卡片），逐张演示 Markdown、填空、
  单选、多选、代码高亮、KaTeX 公式、点击揭示、批注、折叠块、标签页、文字遮盖、
  高亮与上下标、图片、提示框、伸缩大纲等用法，导入后即可自检。

## 实现要点

模板里的 `<script src="./_quizify.db35b34de1.js">`、`<script src="./_persistence.f3b6dfb2c4.js">`
等引用对应媒体库里的同名文件，由 `quizify_addon/runtime_media.py` 统一生成。

### 运行时为什么按内容哈希命名

Anki **不会覆盖已存在的同名媒体文件**：导入 `.apkg` 时同名文件直接跳过，AnkiWeb
的媒体同步同样如此。旧版如果固定叫 `_quizify.js`，那么手机、平板一旦装过任意一个
历史版本，之后所有升级都会被静默跳过——卡片里就一直显示原始的 `%%文字%%`。

因此 `notetype.py` 在生成模板时，会把 `templates/front.html` 里的
`./_quizify.js`、`./_quizify.css`、`./_quizify-i18n.js`、`./_persistence.js` 改写成
带内容哈希的名字（`_quizify.<sha256 前 10 位>.js`）。构建、导入、媒体同步都换成了
设备上从未出现过的文件名，也就不存在“被跳过”的情况；内容没变的资源名字保持不变，
依然会被正常跳过，不会重复占空间。

被替换下来的旧文件名会留在媒体库里（不影响使用），需要清理时用
Anki 的「工具 → 检查媒体 → 删除未使用的媒体」。

打包时有两个坑需要绕开：

1. **Anki 的媒体扫描只认“样式里出现的、以下划线开头的文件名”。** 新版 Rust 导出器
   （`export_anki_package`）不会把仅在笔记类型 CSS 里被 `@font-face` 引用的 KaTeX
   字体收进包，会静默丢失。因此构建脚本改用旧的 `AnkiPackageExporter`，它会扫描
   笔记类型的 CSS。
2. **字体文件不在卡片模板里出现，模板引用也无法触发收集。** 于是构建脚本把所有
   需要随包的资源统一为 `_` / `_quizify-` 前缀，并把它们的文件名写进笔记类型 CSS 的
   一段注释（`/* quizify-mobile-assets:v1 ... */`）。这样导出器会把**全部**运行时
   资源与示例图片都收进包。注意注释里列的是**哈希后的**文件名，必须和
   `package_assets()` 写入媒体库的名字完全一致，否则导出器收不到这些文件。

> `_quizify.css` 里 `@font-face` 引用的 20 个 KaTeX 字体由打包器生成，
> 名字里本来就带内容哈希，因此不需要再改写。

> 不要采用“导出后重写 zip”的方案：实测在当前 Anki 版本中，即便字节完全一致地
> 重新打包，导入器也可能丢掉媒体条目。让导出器一次到位才是可靠的。

## 手机端 / 电脑端怎么用文字遮盖

**复习（手机、平板和电脑一样）**

1. 打开卡片，`%%文字%%` 覆盖的地方默认显示成绿色色块；
2. **点一下色块**就揭示文字；再点一次重新盖上；
3. 卡片里有多个遮盖块时，每个都独立开关，互不影响；
4. 键盘（桌面端）可以 Tab 聚焦遮盖块，按 Enter 或空格切换。

> **答案面会自动揭示**：翻到背面（显示答案）时，遮盖块默认全部展开成正常文字，
> 不需要一个个点开；想再自测时点一下就能重新盖上。正面（题干）始终保持遮盖。

**制作（在电脑上写）**

1. 在 `Front` / `Back` 字段里把要盖住的文字用 `%%` 包起来，例如
   `TCP 是一种 %%面向连接%%、可靠的 %%传输层协议%%。`；
2. `%%` 必须成对，中间不能换行，也不能再出现 `%`；只有一个 `%%` 时
   编辑器诊断面板会提示“没有配对”；
3. 同一段文字可以放多个遮盖块，也可以放进标题、列表、表格等任意正文位置。

> 遮盖块只是把文字“盖上”，文字本身仍留在字段里，所以揭示时周围排版不会跳动。
> 它也**不会**出现在链接标签或图片说明里：在 `<a>` 内部会保持字面文本。

## 升级与多端同步

因为运行时按内容哈希命名，升级只有一步：**重新导入新的 `.apkg`，或者等 AnkiWeb
同步把新的媒体文件传过去**。不需要事先删除媒体库里的旧文件。

需要注意 Anki 自己的一条规则：如果本地已经存在同名的 `Quizify Markdown` 笔记类型
且模板不同，导入**不会**原地更新它，而是把包里的笔记类型另存为 `Quizify Markdown+`，
并连带导入一份新的示例笔记。所以：

- 只想升级示例牌组时，先删掉旧的 `Quizify Markdown` 示例牌组（笔记进入回收站），
  再导入，卡组和笔记类型都不会重复；
- 如果你在旧的 `Quizify Markdown` 笔记类型下写过自己的卡片，导入后可以先用
  「浏览 → 全选 → 更改笔记类型」把它们迁到新的笔记类型，再删除旧笔记类型；
- 手机上同理：先在牌组列表里删掉旧的 Quizify 牌组，再导入新的 `.apkg`。

## 使用与限制

1. 在手机上打开 `Quizify Markdown` 牌组下的卡片即可复习，内容按 Quizify 语法渲染。
2. 在桌面端创建新笔记时选择导入进来的 `Quizify Markdown` 笔记类型，即可继续编写。
3. 手机端**没有**这部分桌面能力：编辑器工具栏、Markdown 批量导入对话框、桌面级
   字段边界校验。这些属于加载项功能，`.apkg` 不含 Python 代码。
4. 悬浮复习控制仍可用于本地逐项揭示；自动翻面与拖拽评分依赖客户端的
   JavaScript 桥接，AnkiDroid 通过其正式/兼容 API 在支持时启用。
5. 复现同样的卡片样式时，桌面端加载项会把运行时挂载到常驻 WebView 头部；`.apkg`
   里的模板则把运行时直接内嵌在模板中（这正是除桌面外的客户端所使用的兼容路径）。
